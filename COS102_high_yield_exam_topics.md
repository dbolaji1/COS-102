## Study Priority

### 1. Algorithms and algorithmic solution design/analysis

This should be studied first because algorithms are the core bridge between problem understanding and program implementation. The topic appears in dedicated algorithm decks, the Course Guide, the Course Material, the Full Course Summary, and assessment sections. It also supports later topics such as pseudocode, flowcharts, C control flow, decomposition, recursion, and computational approaches.

### 2. Flowcharts and pseudocode

This should be the second priority because the repository gives it four dedicated slide decks and a full Course Material study session. It is also easy for examiners to convert into direct questions: define, compare, identify symbols, draw a flowchart, or write pseudocode.

### 3. Problem-solving process, problem types, strategies, and computational approaches

This is the conceptual base of COS 102. Study it after algorithms/representations because it explains why different solution approaches are needed. It is especially likely to support theory questions such as routine vs non-routine problems, solvable vs unsolvable problems, brainstorming, heuristics, trial and error, means-ends analysis, divide and conquer, greedy algorithms, and dynamic programming.

### 4. C programming fundamentals and control flow

This is a high-priority practical area. The Course Material devotes extensive coverage to C syntax, data types, operators, expressions, input/output, branching, and loops. These topics are likely to appear in code-writing, code-tracing, and short explanation questions.

### 5. Modular programming and software design

This is the main later-course theme. It builds on earlier ideas of decomposition and problem breakdown. Focus on functions, modules, recursion, arrays, abstraction, objects, cohesion/coupling, and refactoring because these concepts repeatedly appear across slides and summaries.

## Repeated Cross-Source Concepts

The following ideas appear repeatedly across multiple materials and should be treated as especially important:

- **Breaking problems into smaller parts:** appears as decomposition, divide and conquer, modularisation, functions, modules, and recursion.
- **Sequence–selection–iteration:** appears in algorithms, pseudocode constructs, flowcharts, and C control flow.
- **Input–process–output:** appears in problem understanding, algorithms, flowcharts, pseudocode, C input/output, and testing logic.
- **Abstraction and information hiding:** appears in problem-solving strategies, abstraction, program objects, decomposition/modularization, and software design.
- **Testing, debugging, evaluation, and refactoring:** appears in Introduction to Problem Solving II, Course Material outcomes, decomposition/refactoring, and the software testing materials. It is important, although it did not rank above the five broad topics above because it has less cross-course repetition than algorithms, representations, problem-solving foundations, C fundamentals, and modular design.
